# GravelKing Pro Handover

## Current state

The latest work implemented authenticated, user-isolated JAX artist memory plus the requested songwriting and Library UX changes.

### Completed

- Added `artist_profiles` Drizzle schema:
  - `lib/db/src/schema/artist_profiles.ts`
  - Exported from `lib/db/src/schema/index.ts`
  - Scoped by authenticated database user ID
  - Includes:
    - `memoryEnabled`, default `true`
    - bio, genre, subgenres, tempo
    - stylistic rules
    - life events
    - emotional history
    - storytelling themes
    - lyrical cadence
    - vocal style
    - vocabulary habits
    - timestamps

- Added authenticated artist-memory API routes in:
  - `artifacts/api-server/src/routes/jax.ts`
  - `GET /api/jax/artist-profile`
  - `PUT /api/jax/artist-profile`
  - `DELETE /api/jax/artist-profile`
  - Every database query is constrained with:
    - `eq(artistProfilesTable.userId, req.dbUser.id)`

- Updated `/api/jax/generate`:
  - Loads the profile server-side using `req.dbUser.id`
  - Ignores client-supplied profile data as the persistent source of truth
  - Injects profile data into the JAX prompt only when `memoryEnabled === true`
  - Uses `{}` when disabled or unavailable

- Updated `artifacts/gravelkingpro/src/pages/songwriting.tsx`:
  - Removed the visible Past Sessions drawer
  - Removed the sessions sidebar toggle
  - Removed session cards and delete-session dialog from the UI
  - Removed the lyric card `onTouchEnd` handler
  - Kept native button `onClick` behavior with touch manipulation
  - Replaced localStorage-only artist profile with backend persistence
  - Added “Personalize JAX Memory” toggle, default enabled
  - Added “Clear Memory” button
  - Added fields for the expanded artist dossier
  - Added loading/success/error toasts for generation
  - Routes completed generations to:
    - `/library?track=<trackId>`

- Updated `artifacts/gravelkingpro/src/components/layout.tsx`:
  - Added Library to the primary navigation.

- Existing Library behavior already supports:
  - `?track=<id>`
  - Selecting the generated track
  - Showing it in the top player
  - Pinning it if desired

## Main proof pattern

```ts
const user = req.dbUser;

const [artistProfileRow] = user
  ? await db
      .select()
      .from(artistProfilesTable)
      .where(eq(artistProfilesTable.userId, user.id))
      .limit(1)
  : [];

const artistProfile = artistProfileRow?.memoryEnabled
  ? JSON.stringify({
      bio: artistProfileRow.bio,
      genre: artistProfileRow.genre,
      subGenres: artistProfileRow.subGenres,
      tempo: artistProfileRow.tempo,
      stylisticRules: artistProfileRow.stylisticRules,
      lifeEvents: artistProfileRow.lifeEvents,
      emotionalHistory: artistProfileRow.emotionalHistory,
      storytellingThemes: artistProfileRow.storytellingThemes,
      lyricalCadence: artistProfileRow.lyricalCadence,
      vocalStyle: artistProfileRow.vocalStyle,
      vocabularyHabits: artistProfileRow.vocabularyHabits,
    }).slice(0, 24_000)
  : "{}";
```
